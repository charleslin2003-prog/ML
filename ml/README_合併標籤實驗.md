# 追加實驗：把三個誹謗類罪名合併成一類

延續 `ml/README.md`「已知限制」提出的假設：`加重誹謗`／`散布文字誹謗`／`誹謗` 在刑法上
同屬**第 310 條**的不同態樣，判決書用詞本身就不一致，5 類任務裡這三類的 F1 普遍只有
0.17～0.41，明顯低於 `公然侮辱`（0.6 up）。這份追加實驗驗證：把這三類合併成一個粗類
之後，分數會不會回升。

**這是一份完全獨立、不覆寫既有結果的追加實驗**：

| | 原始 5 類任務 | 追加的 3 類合併任務 |
|---|---|---|
| 資料準備 | `prepare_data.py` | `prepare_data_merged.py`（新檔案） |
| 資料輸出 | `data/` | `data_merged/`（新目錄） |
| 模型資料夾 | `01`～`05` | `06`～`10`（新資料夾，模型與超參數逐一對應） |
| `common.py` | 沿用 | 沿用（加了 `data_dir` 參數，預設值不變，`01`～`05` 行為不受影響） |

## 標籤定義

```
公然侮辱  → 公然侮辱（不變）
加重誹謗  ┐
散布文字誹謗 ├→ 誹謗類
誹謗     ┘
無罪    → 無罪（不變）
```

## 順帶回收了原本被丟棄的資料

`prepare_data.py` 是在合併前的 5 個細分標籤上抓「同一句話被貼過不只一種標籤」的矛盾
資料整批丟棄（2,736 個不同句子）。這份合併實驗改成在**合併後**的 3 個粗類上重新抓矛盾——
一句話先前若只在「加重誹謗」和「誹謗」之間搖擺，合併後兩者都算「誹謗類」，就不再是矛盾，
可以保留。因此合併版的可用資料比原本略多：

| | 5 類任務 | 3 類合併任務 |
|---|---|---|
| 可用列數 | 26,721 | 27,088 |
| 判決數 | 6,990 | 7,048 |

切分方式與原任務相同：以「原文網址」（判決）為 group 切 70/15/15，同一份判決不會
同時出現在 train 和 test。

## 對應的模型資料夾

| 資料夾 | 對應 5 類任務的哪個資料夾 | 模型 |
|---|---|---|
| `06_bert-base-chinese_merged/` | `01` | google-bert/bert-base-chinese |
| `07_chinese-bert-wwm_merged/` | `02` | hfl/chinese-bert-wwm |
| `08_chinese-roberta-wwm-ext_merged/` | `03` | hfl/chinese-roberta-wwm-ext |
| `09_chinese-legal-electra-base_merged/` | `04` | hfl/chinese-legal-electra-base-discriminator |
| `10_lawformer_merged/` | `05` | thunlp/Lawformer |

模型與超參數逐一對應 01～05，只換了資料來源，這樣兩組結果可以直接對照，
分數差異能歸因於「標籤粒度」而不是「換了模型設定」。

## 執行

```
python ml/prepare_data_merged.py                       # 已執行過，產生 data_merged/
python ml/06_bert-base-chinese_merged/train.py          # 逐個訓練
...
python ml/compare_merged.py                             # 彙總成 RESULTS_merged.md
```

五個模型會排在原本 01～05 的訓練佇列之後自動接續執行（同一張 GPU 無法同時跑兩個任務）。

## 怎麼判讀結果

- 若 `誹謗類` 的 F1 明顯高於原本 `加重誹謗`／`散布文字誹謗`／`誹謗` 三者的 F1，且
  `公然侮辱`／`無罪` 的 F1 沒有明顯下降 → 支持「標籤太細」的假設，代表下游應用
  拿掉細分三罪名、只留「有無誹謗」的判斷更實際可用。
- 若合併後 `誹謗類` 的 F1 仍然偏低（例如仍低於 `公然侮辱`）→ 代表混淆不只是
  細分罪名之間的問題，可能整個「誹謗」語意本身（需要「指摘具體事實」）就比
  「公然侮辱」（單純謾罵）更難從單句言論判斷，跟標籤粒度無關。
