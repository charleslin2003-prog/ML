# 第三種實驗：提升準確度

前兩種實驗（`01`~`05` 的 5 類、`06`~`10` 的 3 類合併）都只在**換模型**，
資料本身從頭到尾沒有再處理過。這第三種實驗反過來：**固定住最佳模型，改動資料與訓練技術**，
看準確度還能推多高。

**完全不動原始資料**：`ml/data/`、`ml/data_merged/` 唯讀，另外備份一份在
`ml/_backup_original/`（已用 md5 驗證一致）。所有新資料寫在
`ml/exp3_accuracy/data_*/`。

---

## 1. 資料如何整理才能提高準確度

先實際翻了資料，問題比想像中嚴重。抽樣 25 筆 `無罪` 類的內容，真正是「被告在網路上
發表的言論」的大概只有三分之一，其餘都是 fallback 抽取規則把判決書裡**任何**引號內容
都當成言論抓進來的結果：

| 雜訊類型 | 佔比 | 實際例子 |
|---|---|---|
| **判決書排版的換行＋縮排空白** | **51.4%** | `信口開河、無知\n    亂講` |
| 第三人稱法律敘事 | 5.9% | `林雪紅是於101年3月14日中午，在楠梓區調解委員會3樓辦公室內跟伊說…` |
| 機構／公司名 | 5.1% | `優佳學校財團法人即高雄市私立優佳國民中學`、`今夜卡拉OK店` |
| 法院／判決書引用 | 2.7% | `至被上訴人雖另遭臺灣高等法院臺中分院以102年度上易字第135號民事判決…` |
| 法庭問答逐字稿 | 2.3% | `（問：你是否有把這段話告知乙○○？）我應…` |
| 純英數代號 | 3.1% | `P002 46`、`awaycoffee` |
| 法律術語 | 0.7% | `確定故意（直接故意）`、`不確定故意（間接故意）` |

這些雜訊在三個類別間分布相當平均，所以不是「某一類特別髒」，而是**整體訊噪比偏低**。

### 做了哪些整理

**(a) 空白／換行正規化** — 影響最大的單一處理，涵蓋 51% 的資料。
判決書原文是分欄排版，抽出來的文字帶有大量換行與縮排空白。中文不靠空白分詞，
這些空白只會讓 tokenizer 切出一堆無意義 token，稀釋真正的語意訊號。
順帶把 `．．．` 統一成 `…`、全形空白轉半形。

> 附帶發現：正規化後有 484 筆資料的長度掉到 6 字以下被濾掉——代表它們原本是
> **靠空白撐過最小長度門檻**的，本來就不該留著。

**(b) 非言論列過濾** — 用上表的樣態規則丟掉法庭問答、法條引用、第三人稱法律敘事、
機構名、純代號、法律術語。

**(c) 提高最小長度門檻 6→10 字** — 6~9 字區間裡充斥 `其他已婚同仁`、`今夜卡拉OK店`
這種沒有判斷依據的碎片。

**(d) 正規化後重新去重** — 原本的去重是在正規化**之前**做的，所以
`幹你娘\n  勒` 和 `幹你娘勒` 會被當成兩筆不同資料；正規化後才去重能真正抓到重複。

### 資料變體

| 變體 | 處理 | train 筆數 |
|---|---|---|
| `v0_baseline` | 不處理（等同 `data_merged`，用來驗證實驗管線能重現基準線） | 18,590 |
| `v1_normalize` | 只做空白正規化 | 18,106 |
| `v2_denoise` | 正規化 + 雜訊列過濾 | 15,173 |
| `v3_denoise_len10` | 正規化 + 雜訊過濾 + 最小長度10 + 重新去重 | 10,999 |
| `v3_cleantest` | 同上，但**連 test set 也一起清洗**（只用於第二組評分） | 10,999 |

## 2. 其他提升準確度方案

資料之外還試了這些技術手段（都疊加在資料面勝出的變體上）：

| 方案 | 做法 | 為什麼可能有用 |
|---|---|---|
| **類別加權損失** | 用類別頻率倒數加權 `CrossEntropyLoss` | 評分指標是 macro-F1（每類等權），但預設的 loss 是每筆等權，等於在最佳化 accuracy 而不是 macro-F1 — 加權直接對齊訓練目標與評分目標 |
| **更多 epoch + early stopping** | 6 epochs，連續 2 次 val macro-F1 沒進步就停 | 原本固定 3 epochs 是拍腦袋定的，從未驗證是否收斂 |
| **更大的模型** | `chinese-roberta-wwm-ext-large`（326M，是 base 的 3 倍） | base 模型可能容量不足以區分細微語意；large 需要降 batch 到 16、lr 降到 1e-5 才塞得進 8GB |

### 評估過但這次沒做的方案

- **Ensemble（多模型投票）**：確定能再加一點分數，但推論成本變 3~5 倍，
  且無法回答「哪個因素有效」，留待資料面確定後再考慮
- **資料增強（回譯、同義詞替換）**：這批資料是髒話、諧音字、火星文，
  回譯會把語氣完全洗掉，風險大於效益
- **階層式分類**（先分「侮辱 vs 誹謗」再細分）：目前已經是 3 類，拆層的空間不大

## 3. 測試驗證方法

### 公平比較的關鍵設計

**所有實驗都在同一份未過濾的 test set（4,314 筆）上評分。**
這點很重要：如果連 test set 都一起過濾，分數一定會變好看，但那是因為
「把難的題目刪掉了」，不是模型變強——那樣跟基準線就沒得比。

- 空白正規化屬於**前處理**（train/test 都套用、不刪列），test 筆數不變 → 可直接比較 ✅
- 雜訊過濾屬於**刪列**，只套用在 train/val，test 維持原樣 → 可直接比較 ✅

另外再用「連 test 也清洗過」的版本（2,528 筆）評一次，代表
**實務部署情境**：真實上線時你只會拿真的網路留言去分類，不會拿判決書裡的
法條引用去問模型。這組分數不能跟基準線比，但能回答「這個模型對真實留言有多準」。

### 消融設計

分兩階段，每次只改一個變數：

- **階段1（資料面）**：固定 `chinese-roberta-wwm-ext` + 3 epochs + 無加權，
  只換資料變體 → 隔離出「資料整理」的貢獻
- **階段2（技術面）**：固定在階段1 勝出的資料上，逐一疊加類別加權、更多 epoch、
  更大模型 → 隔離出「訓練技術」的貢獻

`E0_baseline` 跑的是未經處理的資料，用來確認這套新的實驗管線能重現原本
`08_chinese-roberta-wwm-ext_merged` 的 0.5232——如果 E0 跟它差太多，
代表管線本身有問題，後面的比較都不能信。

### 怎麼判讀結果

重跑同一個設定的正常波動是 ±0.013（見 `ml/RESULTS_rerun_check.md`），
所以**提升幅度要超過 0.013 才算真的有效**，否則可能只是 fp16 訓練的隨機誤差。

# 實驗結論（實測後回填）

完整數字見 [`RESULTS_v3.md`](RESULTS_v3.md)。**最佳設定 `E5_weighted_6ep` 把 macro-F1
從 0.5232 推到 0.5409（+0.0177，相對提升 3.4%），而且訓練時間跟基準線一樣只要 7 分鐘。**

## 結論一：資料清洗沒有用，過濾越兇越差（原假設被推翻）

| | train 筆數 | macro-F1 |
|---|---|---|
| 不處理 | 18,590 | 0.5232 |
| 空白正規化 | 18,106 | 0.5247（+0.0015，雜訊內）|
| ＋雜訊過濾 | 15,173 | 0.5168（−0.0064）|
| ＋長度10＋去重 | 10,999 | **0.5029（−0.0203，顯著變差）** |

最有說服力的反證是**清洗過的 test set 分數並沒有比較高**（0.5156 vs 0.5232）。
如果那些被判定為「雜訊」的列真的是無法分類的垃圾，把它們從測試集刪掉應該讓分數**上升**
才對——結果反而略降，代表**那些列並不比其他資料難分類**，模型確實有從中學到東西。

所以瓶頸不在「資料髒」。真正的限制是任務本身：`無罪` 是**判決結果**而不是言論的性質，
同一句髒話可能因為「證據不足」或「可受公評之事」而無罪，單看一句話根本無從判斷。
這是標籤定義的天花板，再怎麼清洗資料都突破不了。

## 結論二：真正有效的是讓 loss 對齊評分指標

| 方案 | macro-F1 | 對基準線 | 成本 |
|---|---|---|---|
| **類別加權損失** | 0.5377 | **+0.0145** | 零（同樣 7 分鐘）|
| **＋6 epochs＋early stopping** | **0.5409** | **+0.0177** | 零（early stopping 讓它仍然 7 分鐘跑完）|
| roberta-large（326M，3倍大） | 0.5281 | +0.0049（不顯著）| **105 分鐘（15倍）＋ 8.3GB 快爆卡** |

原因：評分用的是 **macro-F1（每個類別等權）**，但預設的 loss 是**每筆樣本等權**——
等於訓練時在最佳化 accuracy、評分時卻看 macro-F1，**兩個目標從頭到尾沒有對齊**。

看提升來自哪裡就更清楚了：

| 類別 | 基準線 F1 | 加權後 F1 | 變化 |
|---|---|---|---|
| 公然侮辱 | 0.5523 | 0.5295 | −0.0228 |
| 誹謗類 | 0.6348 | 0.6358 | +0.0011 |
| **無罪**（最弱、最少的類）| 0.3825 | **0.4575** | **+0.0750** |

基準線模型只猜了 1,062 次「無罪」，但測試集裡真的有 1,249 筆——**系統性地少猜少數類別**。
加權後改猜 1,304 次，逼近真實分布，最弱的類別因此大幅改善，拉高了整體 macro-F1。

## 結論三：增加資料量效果有限且不穩定

| 方案 | train 筆數 | macro-F1 | 對基準線 |
|---|---|---|---|
| 放寬到 4 字 | 20,945 | 0.5255 | +0.0023（不顯著）|
| 放寬到 2 字 | 23,422 | 0.5359 | +0.0127（接近門檻）|
| 放寬到 4 字＋加權 | 20,945 | 0.5392 | +0.0160（顯著，但不如單純加權的 +0.0177）|

把原本被 6 字門檻濾掉的短句撈回來（`死賤女人`、`你娘的機掰` 這類典型辱罵），
方向是對的但效果不穩定；而且疊加在類別加權之上**沒有加成效果**（E9 0.5392 < E5 0.5409）。

## 給下一步的建議

1. **立刻可以用**：把類別加權損失套進 `ml/common.py`，所有模型都能免費拿到 +0.015 左右
2. **真正的天花板在標籤**：想再往上推，要處理的是「`無罪` 不是言論性質而是判決結果」
   這個根本問題——可以考慮改成「這句話是否構成誹謗類言論」的二分類（拿掉無罪），
   或者把無罪案件的言論改標成它**被起訴的罪名**而不是判決結果
3. **不要再投資在**：資料清洗（已驗證無效）、更大的模型（15 倍成本換不顯著提升）
